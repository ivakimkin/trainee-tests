# GitHub Pages → Tilda

Публикация согласована владельцем. Фактическое состояние развёртывания проверяйте в Settings → Pages и на сайте GitHub Pages.

## Что согласовать

Меню с четырьмя тестами будет публично доступно по адресу GitHub Pages. Пароль Tilda закрывает только вход через `uralstrateg.ru/test`. Владелец принял эту схему. Вопросы и исходные HTML не изменены. Результаты показываются в браузере и не отправляются на сервер.

## После согласования публикации

1. Загрузить подготовленные файлы в репозиторий `ivakimkin/trainee-tests`, в ветку `main`. Обязательно включить `docs/index.html` и `docs/.nojekyll`. В GitHub можно открыть Add file → Upload files, загрузить index.html внутрь папки docs; .nojekyll добавить через Add file → Create new file, имя `docs/.nojekyll` (пустой файл). Не заменять исходные HTML-тесты.
2. В репозитории открыть Settings → Pages. В разделе Build and deployment выбрать Deploy from a branch, ветку main и папку /docs. Нажать Save. Если уже настроен другой источник, проверить его перед изменением.
3. Дождаться успешного развёртывания Pages и использовать адрес, показанный GitHub. Ожидаемый адрес: https://ivakimkin.github.io/trainee-tests/ . Если GitHub показывает другой домен или путь, заменить src в tilda/github-pages-embed.html.
4. Проверить меню и все тесты по адресу GitHub Pages. Эта ссылка публичная, пароль на ней не установлен.
5. В неопубликованную страницу Tilda с адресом test добавить T123 и вставить ВЕСЬ tilda/github-pages-embed.html. Если ранее вставляли большой HTML-блок тестов, заменить его содержимое, чтобы не дублировать меню.
6. Задать пароль лично в настройках страницы Tilda. Пароль не вставлять в код и не отправлять в GitHub. Проверить, что путь /test не занят другой действующей страницей. Отключить индексацию страницы.
7. После согласования опубликовать страницу Tilda. В приватном окне проверить: запрос пароля, отказ при неверном пароле, загрузку меню при верном, все четыре теста, результат, рекомендации, повторный запуск и возврат. Проверить телефон. Реальный домен и штатная парольная защита Tilda локально не проверены.

## Обновление и проверка

Из корня репозитория: `python3 tools/build_pages.py`. Генератор собирает исходные тесты в docs/index.html, а также обновляет макет и блоки Tilda. Изменения в вопросах вносить в исходные HTML и пересобирать.

Для проверки запустить `python3 -m http.server 8010 --bind 127.0.0.1`, затем в отдельном терминале:

```
TEST_URL=http://127.0.0.1:8010/docs/ node tools/check_tilda.cjs
node tools/check_pages_embed.cjs
```

Требуются Python 3, доступный модуль Node Playwright и Chromium /usr/bin/chromium (есть в подготовленной облачной среде). Вторая проверка перехватывает запросы к двум доменам в Playwright и отвечает локальными файлами: это проверка разных источников и встраивания, а не опубликованного GitHub Pages или Tilda.
