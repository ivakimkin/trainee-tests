# Страница тестов для Tilda

Подготовлено для адреса `https://uralstrateg.ru/test`. Публикация не выполнялась.

## Файлы

- `test-block.html` — целиком вставить в один блок T123 «HTML-код».
- `preview.html` — локальный самостоятельный макет; не заменяет проверку в Tilda.
- `desktop.png`, `mobile.png` — снимки макета из Chromium.
- `../tools/build_tilda.py` — пересборка из четырёх исходных HTML, без изменения их вопросов и ответов.
- `../tools/check_tilda.cjs` — браузерная проверка, требуется Playwright и Chromium.

## Размещение — только после согласования

1. Открыть проект Tilda, привязанный к uralstrateg.ru. Проверить, что путь `/test` не занят действующей страницей; не заменять её без проверки.
2. Создать неопубликованную страницу «Тестирование сотрудников». Задать адрес `test`.
3. Добавить один блок T123 и вставить весь `test-block.html`, включая style и script. Не вставлять содержимое preview.html.
4. В настройках доступа страницы включить штатную защиту паролем. Владелец задаёт пароль лично в Tilda. Не помещать пароль в HTML, JavaScript, Git или переписку. Если тариф или настройки проекта не предоставляют защиту страницы, публикацию остановить до выбора серверной защиты.
5. Отключить индексацию страницы в настройках SEO. Это дополнение к паролю, не защита доступа.
6. В редакторе проверить отсутствие лишних шапок/подвалов и соответствие оформления. Исполнение HTML-кода Tilda может отличаться в предпросмотре и на опубликованной странице; локальная проверка не доказывает работу в Tilda.
7. Перед публикацией согласовать с владельцем макет, адрес и способ защиты. Не публиковать автоматически.
8. После согласования опубликовать страницу и проверить в приватном окне: без пароля содержимое недоступно; неверный пароль не открывает страницу; правильный открывает меню. Убедиться, что HTML тестов не выдаётся анонимному посетителю в исходном ответе и не остаётся на других публичных URL проекта. Проверить все четыре теста на компьютере и телефоне, подсчёт, рекомендации и возврат.

## Поведение и границы

Все тесты встроены в один блок, отдельных публичных ссылок на них не создаётся. Вопросы и исходная логика сохранены; каждый тест работает в sandbox iframe с разрешением только скриптов. Стили и глобальные переменные не влияют на Tilda. Добавлены адаптация ширины, автоматическая высота iframe и выбор ответа с клавиатуры. Возврат в меню запрашивает подтверждение и сбрасывает прохождение. Результаты показываются локально, не сохраняются и не отправляются владельцу. После открытия доступа ответы доступны в браузере: это учебный тренажёр, а не защищённая экзаменационная система.

## Локальная проверка

Из корня репозитория:

```sh
python3 tools/build_tilda.py
python3 -m http.server 8000 --bind 127.0.0.1
# В отдельном терминале, в подготовленной облачной среде:
node tools/check_tilda.cjs
```

Проверка Tilda и парольной защиты на реальном домене остаётся обязательной после подключения редактора и согласования публикации.
